## Slide 7：创新点 1 动机（1 张，1.5 分钟）

**标题**：Modbus 协议结构 → 27 维特征设计

**左侧**（Modbus 4 行主-从交互）：

```
┌─────────────────────────────────┐
│  Row 0: cmd_address   (主→从)     │
│  Row 1: cmd_memory    (主→从)     │
│  Row 2: rsp_address   (从→主)     │
│  Row 3: rsp_memory    (从→主)     │
└─────────────────────────────────┘
       4 行 = 1 个 Modbus 周期
```

**右侧**（27 维构成）：

```
17 维（原始） + 3 维行级 + 8 维窗口级 = 27 维
                                    
行级：time_diff_intra / cmd_resp_diff / address_distance
窗口级：4 个原始特征 × {mean, std, min, max}
```

**视觉**：左图右文对照

## Slide 15：创新点 3 INT8 问题（1 张，1.5 分钟）

**标题**：全 INT8 量化的"慢 1.7×"现象

**问题**：

| 方案 | 模型大小 | 推理延迟 |
|---|---|---|
| FP32 | 29.5 KB | 0.60 ms |
| 全 INT8 | **4.4 KB** | **0.80 ms** ⬆ 慢 1.7× |
| **混合 INT8（本文）** | **5.5 KB** | **0.47 ms** ⬇ 更快 |

**根因分析**：
- 激活 INT8 引入反量化 / dequantize 开销
- SIMD 指令对纯 INT8 流水不友好
- 8 位累加器在 Cortex-M4 上需多次校正

**视觉**：柱状图 + 红色箭头标注"反直觉"

## Slide 16：创新点 3 混合方案（1 张，1.5 分钟）

**标题**：混合 INT8 方案：权重 INT8 + 激活 FP32

**方案设计**：

```
┌─────────────────────────────────────┐
│  权重：对每通道做 INT8 对称量化          │
│        scale[ch] + zero_point=0       │
├─────────────────────────────────────┤
│  激活：保持 FP32                       │
│        避免反量化开销                   │
├─────────────────────────────────────┤
│  BN 折叠：BatchNorm 折叠进 Conv1D     │
│           减少运行时计算               │
└─────────────────────────────────────┘
```

**结果**（对比 FP32）：
- 磁盘：29.5 KB → 5.5 KB（**5.31× 压缩**）
- 推理：0.60 ms → 0.47 ms（**反而更快**）
- 预测一致率：99.80%
- 11 层 SNR：≥ 38 dB 无损

**视觉**：方案设计图 + 数据对比
