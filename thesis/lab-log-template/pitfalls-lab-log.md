# 实验日志常见错误清单（P-L.x 系列）

> 配套 `lab-log.md` 使用。
> 老师可在学生提交初稿时，按本清单检查日志完整性。

---

## 一、目标类（2 类）

### P-L.1 目标宽泛
**典型症状**："调模型"、"跑实验"、"测试一下"。
**正确做法**：1-2 个可验证子目标（"对比 LGB num_leaves 31/63/127 三个值"）。

### P-L.2 目标无验收标准
**典型症状**："看效果"、"试试看"。
**正确做法**：明确"Macro-F1 ≥ 0.83 即采纳"。

---

## 二、环境类（2 类）

### P-L.3 环境不记录
**典型症状**：无 Python / 框架版本；无 GPU 型号。
**正确做法**：用 `pip freeze > requirements.txt` 记录依赖；记录 CUDA / GPU 型号 / 驱动版本。

### P-L.4 Git commit 缺失
**典型症状**：代码改动无版本控制。
**正确做法**：每天 commit 1 次，commit message 注明"对应 exp_xxx"。

---

## 三、超参类（2 类）

### P-L.5 超参不全
**典型症状**："LGB 默认超参"、"Adam 默认 lr"。
**正确做法**：列出所有超参与值，包括默认值。

### P-L.6 数据划分文件未保存
**典型症状**：`train_test_split(..., random_state=42)` 但没保存 train/val 索引。
**正确做法**：保存 `split_2026_09_15.json`，包含所有样本 ID 与标签。

---

## 四、结果类（2 类）

### P-L.7 选择性报告
**典型症状**：只报告好的指标，差的指标（"Minority Recall 仅 0.58"）不写。
**正确做法**：同时报告成功与失败指标。

### P-L.8 关键指标缺失
**典型症状**：只报告 Accuracy，不报告 Macro-F1 / PR-AUC。
**正确做法**：报告 ≥ 3 个指标：Macro-F1 / PR-AUC / Minority Recall。

---

## 五、分析类（2 类）

### P-L.9 无观察分析
**典型症状**："跑完了，结果 OK"。
**正确做法**：至少 2-3 句"为什么这个结果"的分析。

### P-L.10 无下一步计划
**典型症状**：实验做完就停下。
**正确做法**：明确"明天要试什么"。

---

## 六、复现性类（2 类）

### P-L.11 无复现性自检
**典型症状**：未填"复现性检查清单"。
**正确做法**：每天实验结束前填完 7 项自检。

### P-L.12 模型权重未保存
**典型症状**：只报告指标，不保存模型。
**正确做法**：保存 `model_2026_09_15.pkl` / `.pt` / `.txt`。

---
